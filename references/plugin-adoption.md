# 现有插件的明确接管

更新：2026-10-17。该能力已接入已安装 CLI，本机已完成新版迁移；下方规则同样适用于新机器明确接管既有插件。

## 命令与边界

现有安装不能只凭名称相同就自动接管。Agent 的 plan／validate／apply／switch 可附加重复的 `--adopt-plugin REF=SELECTOR`：左侧为已选 Profile 资源键，右侧为准确的原生 `name@marketplace`。

```sh
claude-config plan --machine /absolute/path/to/machine.yaml \
  --agent codex --adopt-plugin code-review@team=code-review@existing-market \
  --format text
```

这仍是完整 Profile 计划，包含选定设置和资源，不是单独执行接管的命令。正式 apply 使用同样映射及 `--expect-plan-id`；预览后任何来源、安装文件或元数据变化都需要重新审阅。该标志是一次执行输入，准确原生名称写入新版私有状态，不加入可迁移 Profile，不引入旧格式运行兼容。

## 核对与执行

- 固定包的原生名称、版本及完整文件／执行位必须匹配现有用户安装。省略 enabled 保留本机状态；明确的 enabled 变化按使用选项报告。
- 同一 marketplace 中已有安装须全部明确选中并接管，或已有新版管理记录；否则更换来源会影响未选插件，整份计划阻断。Claude 项目级作用域仍阻断，不接管它们。
- 保留原生 selector 和缓存文件，将 marketplace 来源转向框架准备的准确固定包。Claude 原生 marketplace add 可替换同名来源；Codex 须通过原生 remove／add 两步更换。两步共用一份日志和恢复边界，不直接编辑插件库存或复制缓存作为安装。
- 无明确接管映射的首次部署发现同名既有插件，会阻断重复安装。已经接管后，以私有状态中的名称执行检查、更新和启用状态导出；其他 marketplace 的同名插件保持原状。
- 版本或内容不匹配返回 `adoption_content_mismatch`，不能借接管执行升级。包装变化须另做明确的版本更新计划及恢复来源。

首次版本变化已有独立的[明确版本更新入口](plugin-replacement.md)，使用不同输入和固定旧来源，不改变接管的匹配条件。

## 缓存与恢复

Claude 库存保留原始 SemVer，但缓存目录把 `+` 编码成 `-`；检查、历史恢复及运行标记处理使用对应端的路径编码，并拒绝不同版本映射到同一目录。

已有其他历史目录只记录为 `retained_versions`，保留原样，不复制进 claudespace、不把正文认作固定历史来源。执行器禁止本次操作改动这些目录；有这类目录时，升级暂时阻断，须另行核对原生缓存清理后再规划。接管本身不会清理它们，也不会授予资源业务信任。原有历史目录中的软链接按链接目标字符串记录，不跟随链接；只要整个保留目录的执行前后快照一致，就允许接管和恢复。新安装或受本次管理的插件版本仍不允许软链接。

纯接管失败／独立 rollback 通过备份恢复来源注册与使用状态，不卸载重装原有文件。来源被移除但新来源尚未添加时也能恢复；出现后续修改则保留现场并报告恢复冲突。正常版本更新仍使用已固定的历史包与原生安装器恢复。

## 本机证据

只读核对摘要（本机历史记录：`deployment/plugin-adoption-review-20261010/README.md`）关联实际安装的统一 JSON 报告。隔离测试分别覆盖 Claude CLI、Codex CLI 和 Codex App 后端的原生来源更换、无重装、再次执行、失败恢复与独立回滚。测试不调用模型、不运行插件业务；本机原生配置、注册、缓存及旧运行入口未写入。
