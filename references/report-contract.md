# 配置检查与操作返回协议

协议版本：1

确定日期：2026-10-09，Asia/Shanghai

状态：统一报告保存、人类输出和交互查看器已实现。2026-10-17 收敛输出参数并修订人类展示；JSON schema_version 仍为 1。

本规范定义 claude-config 新版命令如何向用户和 Agent 返回检查、预览、执行及恢复结果。人类输出和结构化 JSON 必须来自同一份报告数据；既能快速判断结果，也能查清每项合并和冲突如何处理。

配置文件格式、合并算法、检查及写入边界仍由[公共格式与变更规范](../DESIGN.md)定义；本规范是返回协议的唯一维护位置。[实现进度](profile-implementation.md)记录实际支持状态，不把规范描述当成已实现功能。

## 1 适用操作与基本要求

覆盖 plan、validate、apply、export、switch、rollback、fetch-baseline、adopt-baseline、review-conflicts、reconcile-run、retire-skills 和 doctor。将来增加操作时沿用报告结构，补充操作专属内容。

- 检查通过、发现差异、存在冲突和执行失败均形成完整报告。
- 预览与执行明确区分；保存报告属于报告输出，不算部署配置。
- 无变化也返回检查范围、结论和 JSON 地址。
- 不把未检查、未选择或未验证的内容算成通过。
- 展开和查看详情只读取报告，不执行安装、配置写入或冲突决策。
- 冲突有明确策略时可以按既有规则处理，不额外增加每次合并都必须确认的流程。

## 2 人类输出结构

默认使用中文说明，原生字段、资源标识、版本和命令保留准确拼写。固定顺序如下：

| 部分 | 必须说明的内容 |
| --- | --- |
| 操作与结论 | 命令、预览或执行、当前实际结果；失败时直接说明是否恢复及未恢复数量 |
| 对象与范围 | Machine、Agent／App、Profile 和目标配置位置、检查范围 |
| 检查概况 | 检查范围，各对象通过、差异、冲突、失败和未检查情况 |
| 差异与冲突 | 字段或文件、当前与目标内容、原因、采用的处理方式或可选操作 |
| 最终结果 | 是否可执行、是否实际修改、修改结果、失败与恢复情况 |
| 完整报告 | 成功保存的 JSON 文件绝对路径，必要时附私有评审或恢复资料位置 |

正常对象保留紧凑概况，不逐项输出全部成功诊断。详情必须可查询；关键值、对象数量和检查范围不能因此消失。较长路径和内容可以换行，不依赖宽表格才能阅读。

不用“受管设置”“适配版 2”等内部简称解释用户结果。可使用“本次同步的配置”“本机文件在上次同步后被修改”“claudespace 打包修订”。完整版本、指纹和协议内部名称放在详情与 JSON。

每项差异或冲突都有报告内稳定的 ID，如 D1、C1；ID 在静态输出、交互界面和 JSON 中一致。C1 只是展示编号，执行资源决策仍使用准确的 conflict_id。

## 3 交互与非交互展示

| 环境或显式选择 | 展示行为 |
| --- | --- |
| 默认运行，stdin 与 stdout 均连接可用交互终端 | 自动显示可展开报告，包括 tmux 内运行 |
| 非交互、管道、重定向或终端不支持交互 | 静态人类可读报告，不等待输入 |
| 显式选择 text | 静态人类可读报告，即使处于 tmux 或其他终端 |
| 显式选择 json | stdout 只包含一个完整 JSON 文档，不进入交互界面 |

输出接口只保留 `--format auto|text|json`，默认 auto。`--no-input` 已移除，不保留兼容别名；旧命令改用 `--format text`。三个入口的参数错误也遵守指定的 text／json 格式。是否存在 TMUX 环境变量不作为唯一判断依据。

交互操作使用方向键选择、空格展开／收起、Enter 查看详情、q 退出；鼠标不是必要条件。普通差异默认收起，冲突原因和处理建议直接显示，长正文、来源和检查记录按需展开。机械文件变更按资源或框架分组，逐文件值和编号放在子节点；执行与恢复文件清单单独默认收起。窄 tmux pane 中内容应换行，调整窗口后重新布局。

交互界面沿用终端默认底色，标题与分组使用青色粗体，通过／需注意／失败使用绿／黄／红区分；选中行使用整行反显、粗体及 `>` 标记。颜色不可用或设置 `NO_COLOR` 时，保留文字标签、粗体和反显。颜色仅表示已有报告状态，不增加检查结论。默认展开精简的检查对象和注意事项；长路径、完整范围和原因保留在详情中。短报告的快捷键栏紧跟内容，并显示当前可见范围；长报告分页滚动。小于 24 列或 8 行时显示放大提示并继续响应退出键，放大后恢复原报告。

交互查看器在报告生成和保存之后启动。关闭查看器不改变业务结果、退出码或执行决策；返回普通终端后留下结果摘要及 JSON 路径；错误、阻断原因和全部未恢复项仍明确显示，不再次铺开成功文件清单。初始化失败则回退静态输出；不能因查看器故障再次执行业务操作。

静态输出直接列出字段／资源运行参数差异、冲突及其处理方式。仅机械文件复制、框架文件与相同恢复副本可以按对象及相同 action／policy／policy_origin／reason 分组，不能把不同合并策略混在一起；共享配置字段合并仍单独解释。分组显示对象、数量、动作与原因，逐文件编号、原值、路径通过终端子节点和 JSON 查询。成功及已恢复结果按类别与状态计数，失败、未恢复及出错后仍处于 applied 的操作逐项列出。未验证／未检查记录只在名称、原因和状态一致时合并，保留受影响的客户端与资源及检查编号；警告、失败不混入同组。长正文可以引用私有差异资料，但不能只给数量而省略具体对象、原因和处理建议。JSON 模式的进度或额外提示只能写入 stderr，不污染 stdout。

## 4 结果分类与执行状态

| 分类 | 含义 |
| --- | --- |
| 差异 | 当前内容与拟采用内容不同；有合法处理策略时可执行，不等于检查失败 |
| 冲突 | 需要选择处理方式或满足额外条件；未解决且影响本次操作时阻断写入 |
| 检查失败 | 类型、来源、依赖、能力或其他检查不通过，不标成普通差异 |
| 警告 | 需要注意但不阻止本次操作；不能用警告掩盖必要检查失败 |
| 运行错误 | 命令、读取、环境、写入或原生操作未正常完成 |

报告必须分别说明本次操作是否可完成、部署是否可进行。review-conflicts 能生成评审资料，不代表部署冲突已解决；export、adopt-baseline 的成功也不代表原生配置已部署。

fetch-baseline 的结果说明准备好的来源目录、发布记录和下一步采用命令；它不改变配置选择。失败时保留并报告此前已准备的目录，不能把部分获取描述成已全部就绪。来源迁移的采用报告按仓库、路径、提交和 Machine 目录逐项说明变化。

执行状态区分 preview、unchanged、completed、partial、failed；恢复状态另行记录。失败后恢复完成仍是本次执行失败，不能写成部署成功。用户主动选择本次保留时明确列出跳过项和仍存在的偏离，不能报告“全部已同步”。

人类结论必须使用能判断事实的表述，例如“仅预览，未修改配置”“执行已阻断，未修改配置”“更新完成，修改 2 项”“执行失败，已恢复本次修改”或“执行失败，仍有 1 项未恢复”。正文不能只返回 ready／blocked／failed。

检查数量按独立检查记录统计，差异按独立变更项统计，冲突按冲突记录统计；同一冲突因多个关联 blocker 被引用不能重复计数。不同维度不得混加成一个模糊的“问题数量”。

## 5 差异与处理决策

每次新增、覆盖、对象合并、数组替换、保留、跳过、删除和未解决冲突都产生决策记录。不能只返回最终文件，也不使用 Git fast-forward 描述配置处理。

每条决策至少包含：对象和准确路径、来源与目标出处、before／incoming／after、三个值各自的存在标记、action、policy、policy_origin、reason、alternatives 和 check_status。存在标记区分缺失与 null；false、0、空字符串不能误当缺失。

人类详情至少解释“哪个对象发生变化、从什么变成什么、为何这样处理、策略来自哪里、最终保留了什么”。程序默认、Machine、Profile 和本次命令指定的策略均明确标注。

普通数组整体替换必须指出替换范围和被移除内容；资源按标识处理必须指出具体资源及使用状态变化。对象合并时报告选定对象内保留的子项，Profile 切换时报告旧 Profile 留下的项；不扫描并罗列未选择的整个运行目录。

资源正文冲突展示本机变化、来源变化、可选动作及其影响。普通报告不包含完整私有正文或连接资料；长正文通过[私有评审入口](resource-conflict-resolution.md)按权限读取。查看建议不等于已选择建议。

## 6 JSON 结构与身份

统一报告至少包含以下字段。操作不适用的列表使用空列表；无法生成计划或获得对象时使用 null 或明确的未获取状态，不伪造数据。

| 字段 | 内容 |
| --- | --- |
| schema_version | 返回协议版本，初始为 1；独立于 Profile 和 catalog 的格式版本 |
| report_id | 每次运行的独立报告编号 |
| plan_id | 可审阅执行计划的身份；未生成计划时为 null |
| operation | 用户请求的具体操作 |
| preview_only | 是否只预览；与报告文件是否落盘无关 |
| targets | Machine、Agent／App、Profile、配置位置和来源身份 |
| scope | 选定字段与资源、实际检查范围、排除或未验证范围 |
| fingerprints | 来源与目标的准确快照指纹；用于复核而非代替结果说明 |
| status | ok、blocked 或 error，描述本次请求的完成情况 |
| readiness | operation_ready；涉及部署检查时另有 deployment_ready 及其阻断原因 |
| summary | 检查、差异、冲突、警告、变更结果及恢复数量 |
| checks | 逐项检查的对象、结果、错误码和原因 |
| changes | 独立变更项及其关联决策和检查 ID |
| decisions | 所有合并、覆盖、保留、跳过及冲突处理记录 |
| conflicts | 字段和资源冲突、准确 conflict_id、原因、候选动作及状态 |
| blockers | 阻断记录及其关联检查／冲突 ID，不重复生成冲突本体 |
| execution | 执行状态、逐项 results 及实际修改范围 |
| recovery | 是否恢复、逐项结果、未恢复范围和私有恢复资料位置 |
| errors | 安全可读的错误分类、位置、原因及下一步 |
| artifacts | 报告保存状态、JSON 绝对路径，以及本次已生成的评审或恢复资料位置 |

report_id 每次重新运行都不同；plan_id 对应审阅计划，不能用新的 report_id 替代原有执行前计划一致性检查。来源、目标或决策变化后重新规划，过期计划必须阻断。

人类摘要从上述结构计算，不独立维护统计或解释。JSON 包含全部公共明细；敏感数据仍必须脱敏，完整 JSON 不表示无条件导出密钥或私有正文。

### App 启动器使用的目标信息（0.1.4）

当 App Manager 成功加载时，`targets[0]` 额外提供：

| 字段 | 含义 |
| --- | --- |
| `app` | 明确的 App 类型 |
| `application` | Machine 绑定的应用绝对路径 |
| `data_root` | Machine 绑定的原生数据目录绝对路径 |
| `deployment_mode` | 仅 Claude Desktop：从绑定目录的 `claude_desktop_config.json` 只读获得；缺失时为 null，不推断为第三方 |
| `default_third_party_data_root` | 仅 Claude Desktop：当前用户原生第三方目录 `~/Library/Application Support/Claude-3p` 的绝对路径；不是目录重定向选项 |

这些字段描述已读取的绑定和模式，不包含供应商或凭据，不证明账号和会话有效。
模式文件参与既有输入快照；从 plan 到 apply 变化会使计划过期。普通偏好仍读写 `config.json`，第三方功能开关读写 `configLibrary` 已应用的条目；模式文件只读。

Bootstrap 使用明确的 Machine 运行 plan，再以同一 `plan_id` 运行 apply。只有进程成功、`status=ok`、`ready=true`、报告已保存、目标绑定完整且一致、`preview_only=false`、`execution.started=true`、执行状态为 `completed` 或 `unchanged` 才能启动。成功且无变化的 apply 仍是已执行的操作，不能仅接受 completed。

Bootstrap 只支持已准备好的默认第三方数据目录。`data_root` 与 `default_third_party_data_root` 不同必须在 apply 前停止，不能用普通 `open -a` 假称已把 Desktop 重定向到 Machine 指定的任意目录。

## 7 保存与错误处理

常规报告保存在 Machine 的状态目录下 `reports/<report_id>.json`；默认 `<config_dir>/.state`，本机为 `~/claude-config-data/.state`，可用 `runtime.state_dir` 覆盖。报告与私有资源评审、正文基线和恢复 journal 分开。目录权限 0700、文件权限 0600；原子保存后才声明成功。报告是本机运行记录，不进入配置同步仓库。

正常完成、检查阻断和运行失败均尝试保存统一报告。Machine 未能加载等早期失败，使用固定私有目录：macOS 为 `~/Library/Application Support/claude-config/reports`，其他 POSIX 系统为 `~/.local/state/claude-config/reports`，不能随意写入当前项目目录。极早期参数错误也通过统一错误输出尽可能形成报告；标准 --help 不作为检查操作生成报告。

只有文件确实写入成功才能输出“完整 JSON：<绝对路径>”。保存失败时 artifacts 标记未保存、路径为 null，并明确说明原因。业务结果与报告保存结果分别保留；报告保存失败不能将已完成部署说成未修改，也不能为了生成报告重新执行部署。若执行后报告无法保存，仍尽可能说明实际修改和恢复日志位置。

秘密值、认证信息和原生错误文本必须先脱敏；未检查的任意异常文本不能直接拼进 stdout 或 JSON。可用的诊断不能全部吞成笼统“失败”：至少保留错误码、对象、出错阶段及安全的处理建议。

## 8 退出码

| 退出码 | 含义 |
| --- | --- |
| 0 | 请求正常完成，包括正常发现可处理差异、无变化以及按规则明确保留／跳过 |
| 1 | 检查不通过，或存在阻断本次请求的未解决冲突 |
| 2 | 命令参数、环境、执行或报告保存发生错误；恢复成功不会抹去执行错误 |

仅存在差异不能返回失败码。与本次请求无关的部署冲突不使成功生成评审材料的操作失败，但必须在 deployment_ready 中明确报告。信号中断遵循常规进程语义，Ctrl+C 可返回 130，并尽可能保留执行及恢复事实。

## 10 实现验收

- 静态和交互展示使用相同报告；各项 ID、统计、状态与保存 JSON 一致。
- 在实际 tmux pane 验证展开、退出、窄窗口、调整大小和静态回退；不能只验证伪终端标记。
- 管道、重定向、stdin 非终端、显式 text／json 均不等待按键。
- 退出查看器后保留摘要与真实 JSON 地址，查看器失败不改变业务执行结果。
- 验证正常、差异、警告、冲突、缺失、null、数组替换、资源保留、预览过期和各操作的不同就绪含义。
- 验证执行部分失败、恢复完成／未完成、报告保存失败以及早期错误；不能虚报成功或保存地址。
- JSON 可独立解析，stdout 无其他文字；敏感值、私有正文和未清洗异常不会泄露。

## 0.6.0 部署一致性扩展

Agent plan 增加 `resource_inventory`，doctor 的 `--resources` 增加 `resource_inventories`；包含来源、归属、原生启停和分类差异，不包含正文或凭据。文件存在不等于原生发现，`native_discovery.status` 保留 `not_verified`。doctor 的 `installation`、`profile_selection`、可选 `app_processes` 与 `storage` 是观察证据，不能推断会话有效。

`doctor --no-save` 明确不写报告；不能显示已保存地址。`retire-skills` 的 `retired_resources` 列出显式退役对象，预览与事务执行仍按公共协议返回。范围与限制见[部署一致性](deployment-consistency.md)。
